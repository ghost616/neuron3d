# n3d_shape 功能说明（神经元空间形状变体：球体 / 立方体 / 圆柱体）

## 项目定位

本模块是 N3D 的**空间形状变体**实现：在**不改连接判据、不改突触半球切分、不引入随机放置、不改训练循环与数据管线**的前提下，把神经元的空间形状从**球体**泛化为**立方体**与**圆柱体**，用于回答"形状是否为继容量、优化、判据之后的第 4 个有效维度"。

- **自包含**：照"二期从一期拷贝"的既有口径，拷贝 `n3d_sphere` 的 `__init__ / utils / data / config / model / train` 与 README 后独立演进；**不 import `n3d_sphere` / `n3d_proto`**。
- **上游零改动**：`n3d_proto` 与 `n3d_sphere` 的源码与既有产物**零改动**，其验收判据仍全绿。
- **与上游产物的物理隔离**：本模块产物一律写入 `checkpoints/n3d_shape/`，验证类运行写入其 `_verify/` 子目录。
- **默认行为回归锚点**：`shape=sphere` 时必须与二期在相同配置下**张量级逐位一致**（`torch.load` 后逐张量 `torch.equal`，依仓库 D1 口径**不比文件 SHA256**）。

## 核心机制：形状 = 生长度量，不是裁剪掩码

二期 `model.py` 的放置为两步：① `keep = dist <= R_max` 裁剪；② `argsort(dist)[:N]` 取离中心最近的 N 个。**第②步本身就是产生球分布的机制**（已实测：仅把第①步换成同尺度立方体裁剪，选取结果与球体逐位相同）。因此本模块**只改第②步的排序度量**，保留"从中心向外取最近 N 个"的语义与全部确定性 tie-break。

| shape | 生长度量 | 等值面 |
| --- | --- | --- |
| `sphere` | `‖p‖₂` | 球（回归锚点，与二期逐位一致） |
| `cube` | `‖p‖∞ = max(|x|,|y|,|z|)` | 立方体 |
| `cylinder` | `max(‖p_xy‖₂, |z| / λ)` | 半径 r、半高 c = λr、轴 = 流向轴的圆柱 |

## 关键几何事实（实现后必须实测替换）

以下数字均为**本机真实运行实测**（`verify_shape.py` 报告与产物，退出码 0），非前置探针。

**层数 `K` 随长径比 λ 改变 —— 这是架构深度变化，不是"外形"变化**。阶段 2 的向量化逐层递推
循环次数 = `K`，故 `K` 同时决定 DAG 深度与逐层递推步数。

| 圆柱 λ | 0.5（扁平） | 1（等轴） | 2（细高） |
| --- | --- | --- | --- |
| `K`（`N=256, H=D=0.10`） | 5 | 9 | 15 |
| `K`（`N=64, H=D=0.15`） | 3 | 6 | 9 |

**同配置（`N=256, H=D=0.10, y=8x8, flow_axis=z, seed=42, space_radius=0`）三形状实测**：

| shape | λ | `E` | `E/N` | `K` | `\|S_in\|` | `\|S_out\|` | `params` | 选取度量 | extents xy | extents axis |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `sphere` | 1 | 736 | 2.8750 | 9 | 193 | 187 | 154864 | 0.721110 | 0.707107 | 0.565685 |
| `cube` | 1 | 713 | 2.7852 | 9 | 195 | 186 | 156409 | 0.565685 | 0.565685 | 0.565685 |
| `cylinder` | 1 | 705 | 2.7539 | 9 | 196 | 193 | 157185 | 0.600000 | 0.565685 | 0.565685 |
| `cylinder` | 0.5 | 679 | 2.6523 | 5 | 189 | 196 | 151671 | 0.824621 | 0.707107 | 0.282843 |
| `cylinder` | 2 | 717 | 2.8008 | 15 | 200 | 199 | 160333 | 0.494975 | 0.424264 | 0.989949 |

**`E / |S_in| / |S_out| / 参数量必然随形状变化**（表面/体积比不同 → 边界神经元占比不同，
而 `S_in` / `S_out` 由"突触孤立"判据决定）。因此"其他不变"只能保证**规则不变**，
**不得**沿用球体的连通性与参数量数字。

**最近邻距恒为 `2H`**：全部 10 组实测偏差在 float32 精度内（`0.299999952 ~ 0.300000000`
对应 `H=0.15`，`0.199999616 ~ 0.199999914` 对应 `H=0.10`）——形状只改度量，不改 FCC 晶格。

**`|S_in|` / `|S_out|` 是逐 seed 的随机量**（已登记纠正记录），**不得当作设计常数**；
上表数值仅对 `seed=42` 成立，凡引用必须同时标注 seed 与跨 seed 波动范围。

**二期 `R_min` 并非严格几何下界的实测披露**：`sphere` 默认口径
`R_min = H·(N/φ)^(1/3) = 0.701840`，而其选取集合实测最大度量 `0.721110 > 0.701840`
（`SMALL` 口径同样：0.663198 vs 0.670820）。故本模块把 `R_min/R_max` 定位为
**公式窗口与回归锚点**，几何守护改由实测诊断量（`selection_metric` /
`selection_metric_within_space`）承担，并如实披露，而非用与实际不符的硬断言掩盖。

## 尺寸窗口与校验

形状专属尺寸窗口 `[R_min, R_max]`（`φ = 0.7405`；`B = H + D`）：

| shape | `R_min`（非重叠容纳下界） | `R_max` | 外接半径系数 `ρ/R` |
| --- | --- | --- | --- |
| `sphere` | `H·(N/φ)^(1/3)` | `B·(N/φ)^(1/3)` | `1` |
| `cube` | `H·(Nπ/(6φ))^(1/3)` | `B·(N/φ)^(1/3)/√3` | `√3` |
| `cylinder` | `H·(2N/(3λφ))^(1/3)` | `B·(N/φ)^(1/3)/√(1+λ²)` | `√(1+λ²)` |

`R_min` 由"最优堆积系数下非重叠放入 N 个半径 H 的神经元所需空间体积"推出，三种形状
**各自代入自身体积**（球 `(4/3)πR³`、立方体 `8s³`、圆柱 `2πλr³`）。
`space_radius = 0.0`（默认）取该形状 `R_min`；显式值须落在 `[R_min, R_max]` 内，
窗口比较取 `1e-6` 相对容差（支持按显示值回填）。窗口为空（极端 λ）则构造期报错。

DEFAULT 口径（`N=256, H=D=0.10`）实测窗口：`sphere [0.701840, 1.403681]`、
`cube [0.565680, 0.810415]`、`cylinder(λ=1) [0.613114, 0.992552]`、
`λ=0.5 [0.772475, 1.255490]`、`λ=2 [0.486629, 0.627745]`；首个空窗口在 λ≈3.235。

[!] **历史缺陷（皋陶审查 E1，已修复）**：`cylinder` 分支原为
`H·(N/(πλφ))^(1/3)·2^(2/3)`，对应把圆柱体积误当 `(4/3)πλr³`，与严格解恒差
`(6/π)^(1/3) = 1.240701`，导致 DEFAULT 规模下 **λ∈(2.20, 3.22) 被误判为"窗口为空"而拒绝**。
现改用严格体积解；回归实测：λ=2.2/2.5/3.0/3.2 全部构造成功且窗口非空，
λ=4.0 仍被正确拒绝，五组受训配置的 `E/K/|S_in|/|S_out|/params/test_acc` **逐项不变**。

可执行的形状专项判据（全部实测通过）：

* **放置选取判据**：选取集合必须**完全等于**"按形状度量 `m` 取最近 N 个 FCC 格点"
  （由 `verify_shape.py` 的 S5 以**独立复算 + `torch.equal`** 核验，不调用 `model` 内部实现）。
  这是防"只改裁剪掩码等于什么都没改"陷阱的最强证据。
* **度量自洽判据**：`model.selection_metric` 必须等于"用 `model._shape_metric` 直接对
  `neuron_pos` 复算得到的最大度量"（冒烟判据 `[15]` + 验证 S4）。
* **配置一致判据**：`model.shape` / `model.cyl_aspect` / `model.circum_coef` 与 `config`
  逐字段一致（冒烟判据 `[15]` + 验证 S3）。
* **窗口公式判据**：`R_min` 必须由**体积不等式就地独立反解**得到（S3b，**不复制实现表达式**）；
  `R_max` / `ρ` 由几何外接系数独立折算；S3e 另核算"`R_min` 处体积够、`0.999·R_min` 处不够"。
* **越界拒绝判据**：超出 `R_max` 的显式 `space_radius` 必须报错（S3c）。
* **负例判据**（验证 S8）：非 `cylinder` 显式传 `cyl_aspect`；极端 λ 导致窗口为空；
  非法 `shape`；`space_radius` 越界。
* **形状生效判据**（验证 S6）：同配置下三形状的 `neuron_pos` **两两不同**；
  `(E, K, extents)` 组合**两两不同**；圆柱 `K` 随 λ 单调变化。
* **连通性下限**：`E >= N`、层数 `K >= 2`、`|S_in| >= 1`、`|S_out| >= 1`
  对三种形状**均须成立**，不成立即构造期报错并附实测值。
* **放置半径判据**：`shape=sphere` 分支保留二期硬断言 `placement_radius <= R_max`
  （实测恒成立）；非球形状**显式豁免**并如实记录 `placement_radius_over_rmax`
  等诊断量（实测 `cube` 1.2090、`cylinder(λ=2)` 1.7157 越界）。

## 配置与 CLI

- `shape: str = "sphere"`（取值 `sphere` | `cube` | `cylinder`）
- `cyl_aspect: float = 1.0`（圆柱长径比 `λ = c/r`，仅 `cylinder` 生效）
- CLI：`--shape {sphere,cube,cylinder}`、`--cyl-aspect R`；**两者都必须纳入 `explicit` 判定与 `apply_overrides`**，否则会被静默丢弃。
- `to_dict()` / `describe()` / 预设同步。

## 产物指纹（防撞名硬要求）

指纹**必须新增形状维度**（`cylinder` 还须含长径比），否则 N/H/D/seed/scope 相同的三种形状会**互相覆盖**（历史纠正记录中的 `verify_<bpe>.pt` 同名互覆同类缺陷）。须附"同配置不同形状产物名互不相同"的可区分性断言。

## 冒烟判据

把二期 15 条冒烟判据同构为形状感知版本，退出码语义保持 0 / 1 / 2。三形状冒烟全绿，且 `sphere` 分支与二期数值一致。

## 验收

形状变体的验收（全部实测，命令与结果一一对应；含离朱两轮 + 皋陶审查后的修订）：

* 编译：`python -m compileall -q n3d_shape` → 退出码 **0**。
* 冒烟：五种形状（sphere / cube / cylinder λ=1 / 0.5 / 2）
  `python n3d_shape/train.py --smoke-test [--shape S] [--cyl-aspect R]`
  → 判据 **16/16 全绿，退出码 0**；负例（非 cylinder 显式 λ、极端 λ 空窗口）→ **退出码 2**。
  默认组合（sphere + SMALL_CONFIG 规模 + `flow_axis=z` + 两个 `any_isolated`）仍写
  `_verify/smoke.pt`，其余组合写 `_verify/smoke_{shape_tag}_...pt`。
  冒烟产物元数据含形状取证与放置诊断量（`placement_radius_over_rmax` 等）。
* 形状验证：`python n3d_shape/verify_shape.py` → **S1–S14 共 143 条断言，143 通过 / 0 失败，
  退出码 0**；`--quick` → **78/78 通过，退出码 0**，写独立文件
  `verify_shape_report_quick.{md,json}`（不覆盖全量报告）。
* 账本校验：`python n3d_shape/verify_full_runs.py` → 独立复算五组产物的
  `test_acc / E / K / |S_in| / |S_out| / params / SHA256` 并与账本比对，**退出码 0**；
  另含 **E1 回归**（5 项"体积反解一致" + 4 项"曾被误拒 λ 现已非空" + 1 项"真实空窗口仍被拒"）。
* 与二期逐位一致：`sphere` 分支在 `DEFAULT` 与 `SMALL` 两种口径下、**27 个张量
  `torch.equal` 全部相等**（`DEFAULT`：`E=736`, `params=154864`；`SMALL`：`E=106`,
  `params=43930`）。依仓库 D1 口径**跨代码路径不比文件 SHA256**，而是 `torch.load` 后逐张量比对。
* 训练对照（`--preset default --epochs 10 --seed 42 --device cpu`，五组共享同一 seed 前提，
  只在形状维度上不同）：sphere **97.59%** / cube **97.57%** / cylinder λ=1 **97.86%** /
  λ=0.5 **97.40%** / λ=2 **97.70%**，各自独立日志与独立产物（名与 SHA256 均两两唯一）。
  **E1 修复后这些指标逐项未变**（放置由度量排序决定、与 `R_min` 无关），故未重跑训练。
  **判定规则（事先固定）：纯探索** —— 只如实报告
  `test_acc / E / K / |S_in| / |S_out| / params`，**不下"有效/无效"结论**；
  须显式声明"单 seed 单点运行，不足以支撑因果结论"。
* 上游回归：`n3d_sphere` / `n3d_proto` 源码 git 干净、既有产物 **62 个 `.pt` 的 SHA256
  逐位不变**、`requirements.txt` 零新增依赖、一期与二期冒烟均退出码 0。

## 离朱独立测试发现的缺陷与处置（第 2 轮修订）

* **D1（error，已修复）**：`config.shape_spec` 原把 cube 与 sphere 归为
  `circum_coef = 1.0`，导致 cube 的 `R_max` 与校验窗口被放大 `√3` 倍

* **D2（warning，不改实现、如实披露）**：`_build_fcc_positions` 的缩放整数 key

  并由 `verify_shape.py` 的 **S14** 如实取证。功能影响实测为无。
* **验证网加固**：原 S3 比对 `model.circum_coef == spec.circum_coef`，两者**同源**
  （自洽性而非正确性），因此 D1 出现时双方一起错而漏检。现改为与脚本内联的**独立公式**
  比对（S3 / S3b），并新增 **S3c**（超 `R_max` 必须被拒）。**拒绝证明**：重新注入 D1 后
  S3/S3b 立即 FAIL、退出码 1；修复版全绿退出码 0。
* **信息项**：I1 报告按模式分名；I2 新增 `verify_full_runs.py`；
