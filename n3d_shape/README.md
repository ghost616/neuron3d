## 1 核心机制：形状 = 生长度量，不是裁剪掩码

二期的 FCC 放置是**两步**（`n3d_sphere/model.py:308` 与 `:316`）：

```text
① keep = dist <= search_radius        # 裁剪
② shell_order = argsort(dist, stable=True)[:N]   # 取离中心最近的 N 个
```

**第②步才是产生球分布的机制。** 已实测：仅把第①步换成**同尺度立方体裁剪**，选取集合与
球体**逐位相同**（因为第②步永远取度量最小的 N 个，与裁剪阈值无关）。因此本模块
**只替换第②步的排序度量**，保留"从中心向外取最近 N 个"的语义与全部确定性 tie-break。

| shape | 生长度量 `m(p)` | 等值面 | 归一化理由 |
| --- | --- | --- | --- |
| `sphere` | `\|\|p\|\|₂` | 球 | 回归锚点（与二期逐位一致） |
| `cube` | `\|\|p\|\|∞ = max(\|x\|,\|y\|,\|z\|)` | 立方体 | 同名范数（p-范数 p=∞） |
| `cylinder` | `max(\|\|p_xy\|\|₂, \|p_axis\| / λ)` | 半径 r、半高 c=λr、轴=流向轴 的圆柱 | 把柱坐标的两个尺度压平到同一尺度 |

**形状只改第②步的度量**，不改连接判据、不改突触半球切分、不引入随机放置。

### 为什么"只改裁剪掩码"等于什么都没改（已知陷阱）

我们**实测**复现过该陷阱：把第①步的 `dist <= R` 换成"同尺度立方体裁剪"后，
`neuron_pos` 与球体**逐位相同**。验证脚本 `verify_shape.py` 的 **S5** 因此不只比对
"张量是否变化"，而是**完全独立地**复算"按形状度量取最近 N 个格点"（不调用 `model` 内部实现）
并与 `model.neuron_pos` 做 `torch.equal` —— 这是"形状真的落在度量上"的最强证据。

## 2 形状专属尺寸窗口 `[R_min, R_max]`

`space_radius` 是**形状的特征空间尺度**：球 = 半径；立方体 = 外接立方体半边长；
圆柱 = 横截面半径（半高 `= λ·space_radius`）。`space_radius = 0.0`（默认）表示取该形状的
公式下界 `R_min`；显式传入必须落在 `[R_min, R_max]` 内，越界在**构造期报错**。

| shape | `R_min`（非重叠容纳下界） | `R_max`（D 邻域完整落在空间内） | 外接半径系数 `ρ/R` |
| --- | --- | --- | --- |
| `sphere` | `H·(N/φ)^(1/3)` | `(H+D)·(N/φ)^(1/3)` | `1` |
| `cube` | `H·(Nπ/(6φ))^(1/3)` | `(H+D)·(N/φ)^(1/3)/√3` | `√3` |
| `cylinder` | `H·(2N/(3λφ))^(1/3)` | `(H+D)·(N/φ)^(1/3)/√(1+λ²)` | `√(1+λ²)` |

其中 `φ = 0.7405`。`R_min` 由"最优堆积系数下非重叠放入 N 个半径 H 的神经元所需空间体积"
推出，三种形状**各自代入自身体积**（`sphere: (4/3)πR³`、`cube: 8s³`、`cylinder: 2πλr³`）；
`R_max` 由二期的 `R_max = B·(N/φ)^(1/3)`（`B = H+D`）按外接半径系数折算回特征尺度。
**`sphere` 分支与二期逐位同式**（回归锚点）。

> ### 修复记录：cylinder 的 `R_min` 曾与自身体积推导不符（E1，已修复）
>
> 原实现写作 `H·(N/(πλφ))^(1/3)·2^(2/3)`，它对应把**圆柱体积误当成 `(4/3)πλr³`**
> （球体积形式）而非真实的 `2πλr³`，与上式**恒差 `(6/π)^(1/3) = 1.240701`**（偏大 24.07%）；
> 同处的推导链还把 `(4/3)πλr³·… = 2πλr³` 写成**不成立的等式**（两者相差 1.5 倍）。
> 实测（`N=256, H=0.1, λ=1`）：实现 `0.760691` vs 严格解 `0.613114`。
>
> **后果**：`R_min` 被抬高后，DEFAULT 规模下 **λ∈(2.20, 3.22) 的合法配置被误判为
> "形状专属尺寸窗口为空"而拒绝**（如 λ=2.5 误报 `R_max=0.521314 < R_min=0.560482`，
> 而按严格解 `R_min=0.451746`，窗口实为**非空**），错误信息还把原因归为
> "该形状装不下 N 个神经元"这一**不实的几何事实**。
>
> **修复**：改用严格体积解 `H·(2N/(3λφ))^(1/3)`。修复后实测：λ=2.2 / 2.5 / 3.0 / 3.2
> **全部构造成功且窗口非空**；真正的首个空窗口在 **λ≈3.235**
> （`R_max=0.414419 < R_min=0.415443` 附近）。
>
> **无回归（逐项实测，本次未重跑训练）**：`E / K / |S_in| / |S_out| / params / test_acc`
> 由**形状度量排序**决定、与 `R_min` 无关，五组受训配置**逐项完全不变**（见 §3 表与 §12.4）。

### 实测披露：`R_min` 不是"放置一定落入其中"的严格几何下界（**sphere 与 cube 都出现**）

`R_min` 是**非重叠容纳的公式下界**；而实际放置由 **FCC 晶格的离散性 + 形状度量排序**决定，
两者并不严格同一，故存在"实选取度量略大于 `R_min`"的现象 —— **不是仅球体口径**：

| 口径/形状 | `selection_metric` | `space_radius`（= `R_min`） | `within_space` | 比值 |
| --- | --- | --- | --- | --- |
| DEFAULT `sphere` | 0.721110 | 0.701840 | **否** | 1.0275 |
| DEFAULT `cube` | 0.565685 | 0.565680 | **否** | 1.0000 |
| SMALL `sphere` | 0.670820 | 0.663198 | **否** | 1.0115 |
| SMALL `cube` | 0.636396 | 0.534535 | **否** | 1.1906 |
| DEFAULT `cylinder(λ=1)` | 0.600000 | 0.613114 | 是 | 0.9786 |
| DEFAULT `cylinder(λ=0.5)` | 0.824621 | 0.772475 | 是 | 1.0675 |
| DEFAULT `cylinder(λ=2)` | 0.494975 | 0.486629 | 是 | 1.0172 |

（修复 `cylinder` 的 `R_min` 后，λ=0.5 的 `within_space` 由"是"变为"否"，
因其严格 `R_min` 变小 —— 这是**公式更准确**的体现，不改变任何放置结果。）

因此本模块把 `R_min` / `R_max` 定位为**公式窗口与回归锚点**，真正守护几何的是构造期的
**实测诊断量**（`selection_metric` / `selection_metric_within_space` /
`placement_radius_over_rmax` / `placement_within_*`），
它们**已接入** `get_topology_stats()`、训练日志与产物元数据（可复核证据，见 §8.2），
而**不是**用一条与实际不符的断言去掩盖它。

**`placement_radius` 与窗口的关系（W2 披露）**：二期 `n3d_sphere` 的断言是
`placement_radius <= R_max`。本模块 **`shape=sphere` 分支完整保留该硬断言**
（实测 `0.721110 <= 1.403681`、`0.670820 <= 1.326395`，恒成立）；
**非球形状显式豁免**，因该断言在其上**实测被违反**：

| shape | λ | `place/R_max`（DEFAULT） | `place/R_max`（SMALL） |
| --- | --- | --- | --- |
| `sphere` | 1 | **0.5137**（窗口内） | **0.5057**（窗口内） |
| `cube` | 1 | **1.2090**（越界） | **1.2993**（越界） |
| `cylinder` | 1 | 0.8308 | 0.9596 |
| `cylinder` | 0.5 | 0.6944 | 0.6690 |
| `cylinder` | 2 | **1.7157**（越界） | **1.5993**（越界） |

即：**非球形状的放置半径确实超出了 `R_max`**（读者不应误以为放置仍在窗口内）。
根本原因是 `R_max = B·(N/φ)^(1/3)/circum_coef` 随 `circum_coef` 变大而变小，
而立方体 / 细高圆柱按 `‖p‖∞`、`max(‖p_xy‖₂,·)` 生长时外接半径本就更大 —— 两者尺度不同源。

## 4 架构深度随形状改变（必须与"外形变化"区分）

**层数 `K` 直接随长径比 λ 变化 → DAG 深度与逐层递推步数改变。**

| 圆柱 λ | 0.5（扁平） | 1（等轴） | 2（细高） |
| --- | --- | --- | --- |
| `K`（DEFAULT） | **5** | **9** | **15** |
| `K`（SMALL） | **3** | **6** | **9** |

这不是"外形"变化，而是**架构深度**变化：阶段 2 的向量化逐层递推循环次数 = `K`
（`_build_level_groups` 按流向轴坐标分层）。λ 越大越细高 → 沿流向轴的可用层数越多 → `K` 越大。

**`E / |S_in| / |S_out| / 参数量必然随形状变化**（表面/体积比不同 → 边界神经元占比不同，
而 `S_in` / `S_out` 由"突触孤立"判据决定）。因此"其他不变"只能保证**规则不变**，
**不能**沿用球体的连通性与参数量数字。

## 5 产物指纹（防撞名硬要求）

指纹**必须含形状维度**（`cylinder` 还含长径比），否则 `N / H / D / seed / scope` 相同的
三种形状会**互相覆盖** —— 正是历史纠正记录中 `verify_<bpe>.pt` 同名互覆导致取证失效的同一类缺陷。

```text
verify_{bpe}_{shape_tag}_N{N}_y{y_in}x{y_out}_H{H}_D{D}_pl{placement}_ax{axis}_is{scope}_rs{scope}_s{seed}[_tag].pt
full_{shape_tag}_N{N}_...                                                                  .pt
_verify/smoke[_ar{arch}]_{shape_tag}_N{N}_...                                              .pt
```

`shape_tag`：`shapesphere` / `shapecube` / `shapecylinder_a{λ}`（**始终**输出，含 sphere）。
实测同配置下 5 种形状 x 3 类产物名 = **15 个名字全部互不相同**（`verify_shape.py` S11）。
默认组合（`SMALL_CONFIG` 规模 + sphere + `flow_axis=z` + 两个 `any_isolated`）仍退化为历史
文件名 `_verify/smoke.pt`，保持既有引用可读；`is_default_smoke` 判定**已纳入 shape 与 λ**
（否则 `--smoke-test --shape cube` 会静默覆盖 `smoke.pt`）。

### 7.1.1 判定声明（事先固定，不得事后挑选有利结果）

本对照为**纯探索**：上表只**如实报告** `test_acc / E / K / |S_in| / |S_out| / params`，
**不对"形状是否有效/无效"下任何结论**。**单 seed 单点运行（`seed=42`，每组 1 次），
不足以支撑因果结论**；`97.40% ~ 97.86%` 的差异落在单 seed 噪声量级内，不得据此排序形状优劣。

### 7.2 读数须知

* `K` 列即**架构深度**（见 §4），它随 λ 变化：λ=0.5 / 1 / 2 → `K = 5 / 9 / 15`。
* `|S_in|` / `|S_out|` 是**逐 seed 随机量**，随突触采样波动；本表全部为 `seed=42`。
* 参数量差异来自 `W_in`（`|S_in|` 列）与 `edge_weight`（`E` 条）随形状变化。

### 7.3 跨 seed 波动范围（`|S_in|` / `|S_out|` 不得当作设计常数）

`|S_in|` / `|S_out|` 是**逐 seed 的随机量**（由突触采样 → 孤立掩码 → scope 判据决定）。
本模块**不把这两个量当设计常数**；上表数值仅对 `seed=42` 成立。凡引用必须同时标注 seed。

**实测波动范围**（`N=256, H=D=0.10, y=8x8, flow_axis=z`，两个 `any_isolated`，
取自二期既有取证日志 `checkpoints/n3d_sphere/_verify/log_full_N256_isany_rsany_s*.txt`，
10 个 seed：0/1/2/3/5/7/43/99/123/2024）：

| 量 | 区间 | 跨度 | 均值 | `seed=42` 取值 |
| --- | --- | --- | --- | --- |
| `\|S_in\|` | **[182, 205]** | 23 | 195.2 | 193 |
| `\|S_out\|` | **[185, 197]** | 12 | 191.7 | 187 |

—— 跨度达 23 / 12（约 12% / 6%），足以说明"`\|S_in\|` 固定为某值"这类表述是错的。
`params` 也因此随 seed 轻微变化（`W_in` 列数 = `|S_in|`）：上表 `params` 差异
既含形状维度、也含 seed 维度，**不能只归因于形状**。

### 7.4 稳健性核验：形状选取与 `space_radius` 无关

按设计，选取集合由 **第②步的度量排序**决定，第①步只限定候选范围，故在窗口内改变
`space_radius` **不应改变形状**。**实测**（`shape=cube, N=256, H=D=0.10`）：

| `space_radius` | 0.0（取 `R_min`） | 0.565680 | 0.70 | 0.810415（=`R_max`） | 1.403681 |
| --- | --- | --- | --- | --- | --- |
| 是否被接受 | 是 | 是 | 是 | 是 | **否**（超 `R_max`） |
| `neuron_pos` 与默认值逐位相等 | 是 | 是 | 是 | 是 | —（构造被拒） |
| `selection_metric` | 0.565685 | 0.565685 | 0.565685 | 0.565685 | — |
| `E` | 713 | 713 | 713 | 713 | — |

这与 §1 的"只改裁剪掩码等于什么都没改"是**同一事实的两面**：裁剪阈值不影响选取。
同时越界值被拒绝（`1.403681` / `1.2` / `1.41` 均报错），窗口校验有效。

> **窗口比较容差说明**：`space_radius` 常按 `R_min`/`R_max` 的显示值（6 位小数）回填，
> 与公式值存在约 1e-7 量级浮点差。实测 `cube/N=256` 的 `R_min` 全精度为
> `0.5656804567776409`，按 6 位小数回填 `0.565680` 会差 `4.57e-7`。故窗口比较取
> **1e-6 相对容差**（远小于"真正越界"的量级），避免"恰好取 `R_min` 的合法值"被误判越界。

## 11 已知陷阱清单（实现与文档均已显式规避）

1. **只改裁剪掩码等于什么都没改** —— 第②步的度量才是机制（§1，S5 守护）。
2. **形状维度不进指纹 = 互相覆盖** —— 指纹必含 shape（+λ），S11 守护 15 名互异。
3. **`|S_in|` / `|S_out|` 是逐 seed 随机量** —— 不得当设计常数，凡引用标注 seed（§7.3）。
4. **`K` 变化是架构深度变化**，不是外形变化 —— 报告须明确区分（§4）。
5. **二期的 `R_min` 不是严格下界** —— 实测选取度量 0.721110 > 0.701840；本模块如实披露
   并用实测诊断量守护，而非硬断言掩盖（§2）。
6. **`--shape` / `--cyl-aspect` 必须进 `explicit` 与 `apply_overrides`** —— 否则被静默丢弃
   （已实现于 `train.build_smoke_config` / `train.apply_overrides` / `Config.to_dict`）。
7. **Windows GBK 控制台**：Runtime 日志/帮助文案禁用 `‖ ₂ ∞ ↔ ⇒ σ` 等非 GBK 字符，
   否则 `--help` 与日志路径抛 `UnicodeEncodeError`（已在新增文案中全部改用 ASCII 记号）。
8. **候选搜索边界 ≠ 几何约束**：搜索半径必须与形状无关地取
   `max(shape_circum_radius, max_space_radius)`。若误用形状外接半径 `ρ` 当搜索边界，
   `DEFAULT` 球体口径下 `ρ = R_min = 0.701840` 内只有 **249** 个格点（< `N=256`），
   默认分支直接无法构造 —— 而二期能正常工作正是因为其搜索半径取 `max_space_radius`。
9. **窗口边界比较需要容差**：`space_radius` 按显示值（6 位小数）回填会与公式值差约 1e-7，
   严格比较会把合法值误判越界（§7.4 实测 `4.57e-7`）。
10. **`params` 要区分"可学习参数"与"`state_dict` 元素"**：后者还含
    `syn_dist [N*y_out, N*y_in]`（`N=256,y=8` 时为 4.19M 元素），会让参数量看起来膨胀 28 倍。
11. **`shape_spec` 的 `circum_coef` 不能用"非 cylinder 一律 1.0"简化** —— 实测缺陷
    （离朱 D1）：cube 少除一个 `√3`，使 `R_max` 与校验窗口放大 `√3` 倍，
    `Config(shape="cube", space_radius=1.0/1.2/1.403681)` 这类**越界配置被静默接受**。
    已修复为 cube 返回 `√3`（§12.1）。
12. **`verify_shape.py` 的 S3 曾与实现"同源自洽"** —— 实测缺陷：原来比对
    `model.circum_coef == spec.circum_coef`，而两者同源于 `config.shape_spec`，
    于是 D1 出现时双方一起错、验证网漏过。已改为与**本文件内联的独立公式**比对
    （S3/S3b），并新增"越界必须被拒"的判据 S3c（§12.1；S3c 只覆盖"给定正确 `R_max` 时的
    越界拒绝"，钉住 `R_max` 绝对值的是 S3b）。
13. **`neuron_pos` 索引顺序不是严格的流向轴升序** —— 继承自二期的缩放整数 key
    `轴坐标·(N+1) + 度量名次` 不满足等价条件（§12.2）。**不要**把它当契约使用。
14. **形状体积不能张冠李戴** —— 圆柱体积是 `2πλr³`（横截面半径 r、半高 λr），
    **不是** `(4/3)πλr³`（球体积形式）。混用会让 `R_min` 恒差 `(6/π)^(1/3) = 1.240701`，
    进而把合法配置误判为"窗口为空"而拒绝（§13.1 E1）。
15. **验证判据不得与实现同源** —— 期望值若直接抄写实现的表达式，校验只能证明
    "代码 == 抄写下来的同一公式"。正确做法是**由几何不等式独立反解**（§13.2 W1 的 S3b/S3e）。
    历史上 D1 与 E1 两次都是同源判据漏检。
16. **删除上游断言必须区分"哪个断言"** —— 二期真实断言是
    `placement_radius <= R_max`（不是 `ρ >= placement_radius`）；该断言在非球形状上实测越界，
    故 sphere 分支保留、非球显式豁免并披露比值（§13.3 W2）。
17. **诊断字段必须真的被读到** —— 只写不读的字段（"死字段"）不构成证据；
    须接入 `get_topology_stats()` + 日志 + 产物元数据（§13.4 I1）。

## 12 离朱实测缺陷与处置（测试后修订记录）

### 12.1 D1（error，**已修复**）：cube 的 `circum_coef` 缺少 `√3`

* **位置**：`config.py::shape_spec`。
* **缺陷**：原实现写作 `if shape != "cylinder": return ShapeSpec(..., circum_coef=1.0)`，
  把 cube 与 sphere 归为一类，导致 `max_space_radius` 少除一个 `√3`。
* **实测证据**：`N=256,H=D=0.1` 下代码窗口 `[0.565680, 1.403681]` vs 文档
  `[0.565680, 0.810415]`，比值恰为 `1.732051 = √3`；`circum_coef` 实测 `1.0` vs 文档 `1.732051`。
* **后果**：`Config(shape="cube", space_radius=1.0 / 1.2 / 1.4036805962168257)` 被**静默接受**。
* **影响面（已隔离）**：`neuron_pos` / `E` / `K` / `|S_in|` / `|S_out|` / `params` /
  `test_acc` **均不受影响**（搜索半径取 `max(ρ, R_max)`，两种取值下候选集合都足够）；
  受影响的是**配置校验严格性**与对外派生量（`R_max` / `circum_coef` / `shape_circum_radius`）。
* **修复**：`shape_spec` 中 cube 分支返回 `circum_coef = math.sqrt(3.0)`。
* **回归实测**：cube 窗口变为 `[0.565680, 0.810415]`（非空）；越界值 `1.0 / 1.2 / 1.403681 / 1.41`
  全部被拒；cube 的 `E=713`、`K=9`、`selection_metric=0.565685` 与修复前**完全一致**；
  sphere 分支 `R_max=1.403681`、`E=736` **不变**（回归锚点未受影响）。
* **防线加固**：`verify_shape.py` 新增 S3（circum_coef 与**内联独立公式**比对）、
  S3b（`R_min`/`R_max`/`ρ` 与独立公式比对）、S3c（超 `R_max` 必须被拒）。
  **负例验证（注入-验证-恢复三步实测）**：把缺陷重新注入后，`--quick` 退出码 **1**、
  失败项恰为 **S3 与 S3b**（且全部为 cube）；从备份恢复后 `config.py` SHA256 与注入前**逐字节相同**，
  `--quick` 回到 78/78、全量回到全绿退出码 0 —— 证明验证网确实能抓住该缺陷（此前抓不住）。

  **判据分工（避免高估 S3c 的作用，离朱 F3 提示）**：钉住 `R_max` **绝对值**的是 **S3b**；
  **S3c 的探针取 `R_max` 的相对倍数**（`R_max×1.001`、`R_max×1.2`），当缺陷同时把 `R_max` 放大时
  S3c **仍会 PASS**。故 S3c 的准确定位是"**给定正确 `R_max` 前提下的越界拒绝判据**"，
  **不是**"D1 类缺陷的独立防线"。实测：注入 D1 后 S3c 未失败，仅 S3/S3b 失败。

  **一次失败的尝试（如实留档）**：为给 S3c 补一个"不依赖 `R_max` 绝对值"的探针，
  先试过"固定 `space_radius = 1.0`"，但**实测该值对 `sphere`（`R_max = 1.4037`）与
  `cylinder λ=0.5`（`R_max = 1.2555`）而言仍在合法窗口内** —— 构造期断言直接把探针本身判错，
  故该探针不可用。又试过"窗口比值自洽性"`R_max/R_min == (B/H)/circum_coef`，
  但**该推导本身不成立**（`R_min` 亦含形状相关体积系数，比值并非该简单形式）：
  在正确代码上实测 cube 为 `1.432638` vs 误推期望 `1.154700`，**断言本身错误**，已删除。
  结论：钉住 D1 类缺陷的**正确**做法就是 S3 与 S3b —— 直接用**绝对公式**与内联期望值比对，
  不去依赖任何"推导出来的关系"。

### 12.2 D2（warning，**不改实现，改为如实披露**）：`neuron_pos` 排序键有损

* **位置**：`model.py::_build_fcc_positions` 的 `lex_key = positions[:, axis] * (N+1) + shell_rank`。
* **事实**：该缩放整数 key 等价于真·字典序 `(轴坐标, 度量名次)` 的**必要条件**是

* **实测偏差**（轴坐标逆序的相邻位置数；本模块独立复算，与离朱结论一致）：

  | 规模 | sphere | cube | cylinder λ=1 | λ=0.5 | λ=2 |
  | --- | --- | --- | --- | --- | --- |
  | `SMALL`（N=64） | 20/63 | 24/63 | — | 22/63 | — |
  | `DEFAULT`（N=256） | 102/255 | 102/255 | — | 86/255 | — |

  `SMALL` 58/64、`DEFAULT` 248/256。
* **为何不在本模块修复**：该 key 公式与二期 `n3d_sphere` **完全相同**，属**继承行为**。

  "默认分支必须与二期张量级逐位一致"。二者不可兼得。
* **功能影响 = 无（已实测）**：① 选取**集合**与独立复算逐位一致（S5）；
  ② `topo_index` 由 `argsort(轴坐标)` **独立**计算、覆盖全部神经元，每条边仍严格上行（S9/S14）；
  ③ `_build_level_groups` 按 `topo_index` 重排后再切层，阶段 2 分层递推不依赖
  `neuron_pos` 的索引连续性；④ DAG 四项判据、冒烟 16/16、验证全部通过。
* **处置**：修正 `model.py::_build_fcc_positions` 的 docstring（删除"索引顺序即沿流向轴升序"
  的错误承诺，改为如实说明并标注为已知遗留口径）；`verify_shape.py` 新增 **S14** 把
  "逆序位置数"与"拓扑序/严格上行仍成立"做成可复核判据。
* **需风后决策的事项**：若要求 `neuron_pos` 严格按流向轴升序，则须**同时**修改二期
  `n3d_sphere` 并重跑二期全部取证（与"二期零改动"冲突，需显式豁免）。

### 13.1 E1（error，**已修复**）：cylinder 的 `R_min` 与模块自身体积推导不符，误拒合法配置

* **问题**：实现为 `H·(N/(πλφ))^(1/3)·2^(2/3)`，而模块自己写下的前提
  `2πλr³ >= N(4/3)πH³/φ` 的**严格解是 `H·(2N/(3λφ))^(1/3)`**，两者**恒差 `(6/π)^(1/3) = 1.240701`**
  （实现偏大 24.07%）。根因是把**圆柱体积误当成 `(4/3)πλr³`**（球体积形式）而非真实的 `2πλr³`；
  同处的推导链还把 `(4/3)πλr³·… = 2πλr³` 写成**不成立的等式**（两者相差 1.5 倍）。
* **实测**（`N=256, H=0.1, φ=0.7405`）：λ=1 实现 `0.760691` vs 严格 `0.613114`；λ=0.5/2 同比值。
* **后果**：`R_min` 被抬高 → DEFAULT 规模下 **λ∈(2.20, 3.22) 被以"形状专属尺寸窗口为空"误拒**

  错误信息还把原因归为"该形状装不下 N 个神经元"这一**不实的几何事实**。
* **修复**：`min_space_radius()` 的 cylinder 分支改为严格体积解 `H·(2N/(3λφ))^(1/3)`；
  推导链与模块 docstring 均改为显式写出圆柱体积 `πr²·(2λr) = 2πλr³` 并给出严格解步骤，
  使 docstring / 模块文档 / 实现三者一致。
* **回归证据**：

## 15 2H 契约的浮点容差缺陷（已修复）

### 15.1 缺陷定界（先复现，再修复）

`_build_fcc_positions` 原先在 `positions.to(torch.float32)` **之后**执行“最近邻距恰为 2H”断言，
容差是**绝对 `1e-6`**。**实测复现**（`cylinder lam=2, D=0.10`，`N` 递增）：

| `N` | 256 | 384 | 512 | 640 | **768** | **1024** |
| --- | --- | --- | --- | --- | --- | --- |
| 结果 | OK | OK | OK | OK | **AssertionError** | **AssertionError** |

失败报文：`[契约失败] FCC 最近邻距必须为 2H=0.2，实测 0.19999872148036957`（偏差 **1.279e-6**）。
**同规模 `sphere` / `cube` @N=1024 通过** -> 在该实测范围内呈**尺度相关**
（λ=2 的 z 跨度最大、`|p|max` 最大 -> float32 `cdist` 舍入误差最大）。
[!] **表述更正（离朱 R6 实测）**：不能一概说成“**不是 N 相关问题**”——同一 `max|coord|` 下
（`cube`，1.131371）N=1700 比值 0.603、N≥1750 比值 1.130，说明 **N 增大本身也会推高
float32 距离域累加误差**。准确表述：N≤1024 的实测范围内呈尺度相关；N 更大时距离域
累加误差亦随 N 增长（见 §15.6）。

实测量化（同一批坐标）：

| 对象 | `nn` | 与 `2H=0.2` 偏差 | 旧绝对容差 `1e-6` | 新尺度感知容差 |
| --- | --- | --- | --- | --- |
| float64 格点 | 0.19999999999999787 | **2.137e-15** | 通过 | 通过 |
| float32 坐标（lam=2, N=1024） | 0.19999872148036957 | **1.279e-06** | **失败（误报）** | 通过（tol=1.556e-06） |
| float32 坐标（sphere, N=1024） | 0.19999946653842926 | 5.335e-07 | 通过 | 通过 |

### 15.2 修复：两道防线

* **第一道（精确契约）**：在 **float64 格点**上校验，即 `.to(torch.float32)` **之前**，
  容差 `1e-9`（float64 实测偏差 `2e-15`，余量 6 个数量级）。
  **契约检查不应受 float32 舍入影响** —— 这是修复的核心。
* **第二道（二次防线）**：对最终 **float32 坐标**（下游实际使用的值）再校验，
  容差 `tol = 1e-6 * max(1.0, max|coord|) + 3e-6`
  （**尺度项**补偿坐标域舍入 `~6e-8*L`；**常数项**补偿 `cdist` **距离域累加**舍入）。
  [!] 常数项系离朱 R6 实测发现同类假阳性后加入（见 §15.6）。

口径已同步至 `model.py` 的 `_build_fcc_positions` docstring、`current_spec.md` 与本文件。

**后置（float32 转换之后）回归的可检下限（皋陶审查 #4）**：
`≈ 1e-6 · max(1, |coord|max) + 3e-6`（`N=3072` 实测约 **4.27e-6 ~ 5.26e-6**）——
**小于该值的后置偏移不会被拓到**（被常数项吸收）；
真实几何偏移由**第一道 float64（容差 `1e-9`）**把守。
两类防线**职责不同、不可互相替代**：第一道管“精确契约”，
第二道管“下游实际用的那份 float32 值也在合理范围内”。

**常数项 `3e-6` 对计划建议公式的偏离及其实测依据（皋陶审查 #4）**：
计划原建议公式为 `1e-6 · max(1.0, max|coord|)`（**无常数项**），实测不足：
常数项取 `0` 时 `N=3072/cube` **构造直接报错**（`dev=2.471e-6 > tol=1.273e-6`）；
而 float32 距离域噪声**饱和于 `≈2.471e-6`**，同一批坐标改由 float64 算距离的偏差为 `5.400e-8`
（即噪声确实来自 float32 距离计算、而非几何）。该偏离经离朱 R6 独立发现并触发加固，
**属有实测支撑的必要偏离**（非事后放宽）。

### 15.3 拒绝证明（不是空转断言）

**（a）注入真实非 2H 偏移** —— 晶格常数 x1.0001（`2H` -> `0.20002`）：
`verify_shape.py --quick` **退出码 1**，由**第一道**断言命中
（`[契约失败] (float64 格点) FCC 最近邻距必须为 2H=0.3，实测 0.3000299999999999`）；
从备份恢复后源文件 **SHA256 逐字节相同**（`19acac8eeb678b56...`），`--quick` 回到 78/78 退码 0。

**（b）更隐蔽的“单点偏离”**（直接作用于坐标）：

| 单点平移量 | float64 偏差 | 第一道（<1e-9） | float32 偏差 | 第二道（尺度感知） | 至少一道抓住 |
| --- | --- | --- | --- | --- | --- |
| `1e-4` | 7.070e-05 | **抓住** | 7.075e-05 | **抓住** | 是 |
| `1e-05` | 7.071e-06 | **抓住** | 7.537e-06 | **抓住** | 是 |
| `1e-06` | 7.071e-07 | **抓住** | 1.279e-06 | 未抓住 | 是 |

**结论**：容差**只补偿 float32 舍入**（1e-6 相对量级），**不是**放宽契约 ——
所有真实的非 2H 偏移（即使小到 `1e-6`）都被第一道 float64 断言捕获。

**必须同时声明的两条限制**：

1. **即使 `params` 已对齐，`E / K / |S_in| / D` 仍各不相同** -> 差异**不可单独归因于形状**。
   实测：`E` 覆盖 1469-1696、`K` 覆盖 9-23、`D` 覆盖 0.064969-0.069000、
   `|S_in|` 覆盖 177-188（ALL/ALL）、`|S_out|` 覆盖 172-194。
2. **参数对齐解不唯一** —— 已实测：`(N=1024, D=0.065)` 与 `(N=2048, D=0.072)` 都能到 ~15.5 万，
   但 `E = 1,527 vs 4,061`、`K = 15 vs 19`。本口径仅为**已声明的一种对齐方案**，
   **不是唯一答案**；换一种对齐方案（不同 `N`、不同旋钮）会得到不同的 `E/K` 组合。

**单 seed 单点**：全部对照共享 `seed=42`，每组仅 1 次运行；
`dacc` 区间 `-0.54 ~ +0.02 pp` 落在单 seed 噪声量级内，**不足以支撑因果结论**。

### 16.4 scope 不影响拓扑（回归锚点）

`E` 与 `K` **只由形状与 `D` 决定，与 scope 无关**。同 `D` 下两种 scope 的实测对比
（`N=1024`，各形状取 ALL/ALL 组的 `D`）：

| 形状 | lam | `D` | `E` (any/all) | `K` (any/all) | `|S_in|` (any->all) | `|S_out|` (any->all) | `params` (any->all) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| `sphere` | 1 | 0.064996 | 1525 / 1525 | 15 / 15 | 1023 -> 181 | 1024 -> 172 | 814,821 -> 154,693 |
| `cube` | 1 | 0.065500 | 1524 / 1524 | 13 / 13 | 1023 -> 183 | 1024 -> 191 | 814,820 -> 156,260 |
| `cylinder` | 1 | 0.065531 | 1523 / 1523 | 15 / 15 | 1024 -> 184 | 1024 -> 190 | 815,603 -> 157,043 |
| `cylinder` | 0.5 | 0.069000 | 1696 / 1696 | 9 / 9 | 1024 -> 177 | 1023 -> 189 | 815,776 -> 151,728 |
| `cylinder` | 2 | 0.064969 | 1469 / 1469 | 23 / 23 | 1023 -> 188 | 1024 -> 194 | 814,765 -> 160,125 |

**`E`/`K` 在两种 scope 下逐形状完全相同** —— 已作为自动断言写入 `verify_full_runs.py`
（`scope 不影响拓扑` 段，10 项全通过）。注意：`|S_in|` / `|S_out|` 与 `params` **会**随 scope 剧变

**故“参数对齐”只能在同一 scope 内比较**，这也是本轮把对齐目标设为“同形状 ANY/ANY”的原因。

### 16.5 与二期「参数对齐后 all_isolated 相对 any_isolated 配对均值 -0.225 pp」的口径差异

**不可直接对比**，因为口径不同：

| 维度 | 二期（`n3d_sphere`） | 本轮（`n3d_shape`） |
| --- | --- | --- |
| `D` 的确定方式 | **逐 seed 重新调参** | 一次搜出、各形状各一个 `D` |
| `N` | **未固定** | **固定 `N=1024`** |
| 对齐对象 | 跨 scope 配对 | **同形状 ANY/ANY** 的 `params` |
| 形状维度 | 仅球体 | 球体 + 立方体 + 圆柱（lam=0.5/1/2） |
| 统计量 | 配对均值 `-0.225 pp`（`0.01<p<0.05`） | 本表 `dacc`，单 seed 单点 |

因此本轮的 `dacc`（`-0.54 ~ +0.02 pp`）与二期的 `-0.225 pp` **在方法学上不同源**，
**不得**据此宣称“复现/反驳”了二期结论。若要与之对话，须先把口径统一
（同样逐 seed 重调 `D`、固定 `N`、并做配对检验）。

> 而该伪影在 `N=3072/4096` 才饱和）—— 该缺口现已闭合。

离朱 R6 独立测试发现：**仅用尺度项的第二道容差在大规模下仍会假阳性**。

**（a）发现的缺口**（合法 2H 配置，float64 精确性均为 ~1e-15，故非真实偏移）。
下表 `N` 为**实测首个失败 `N`**（R6 初测为抽样上界，R8/R9 已定点复核精确化）；
同行 `dev / tol / ratio` 三元组**均为该首个失败 `N` 处的实测值**（口径：加固前容差
`tol = 1e-6·max(1.0, max|coord|)`，无 `+3e-6`）：

| 配置 | 实测首个失败 `N` | 偏差 / 容差（比值） |
| --- | --- | --- |
| `cube D=0.10`（`max\|coord\|=1.131371`） | **1720**（N=1719 通过） | 1.2785e-6 / 1.1314e-6（**1.130**） |
| `cube D=0.072` | **1720**（与 `D=0.10` 同为首个失败 `N`，因 `N<=2000` 内搜索半径覆盖同一批格点、`max\|coord\|` 相同） | 1.2785e-6 / 1.1314e-6（**1.130**） |
| `sphere D=0.10`（`max\|coord\|=1.555635`） | **3256**（N=3255 通过） | 1.8746e-6 / 1.5556e-6（**1.205**） |
| `cylinder λ=2 D=0.10` | **2865**（N=2864 通过） | 2.4706e-6 / 2.1213e-6（**1.165**） |

**（b）根因（本模块独立复测确认）**：被断言的是 `torch.cdist` 在 **float32** 下算出的**距离**，
其误差含两部分 —— ① 坐标域舍入 `≈6e-8·L`（随量级线性，即尺度项）；
② **距离域累加**舍入（`a·a − 2ab + b·b`），**与 `max|coord|` 不同步增长**。
核心证据：****同一批 float32 坐标，改用 float64 计算距离**时，误差落在**离散的量化下限**
`[3.29e-8, 5.40e-8]`（实测 7 档 N × 5 形状 = 35 组：33 组为 `5.40e-8`，
仅 `N=512` 的 `sphere` 与 `cylinder λ=2` 为 `3.29e-8`）；**`N>=768` 全部为 `5.40e-8`**，
且**与 `max|coord|` 无关**。故它是**纯坐标量化的下限**（而非单一常数），
量级 `~3e-8~5e-8`，比 float32 距离域的饱和值 `2.471e-6` 小约 **46~75 倍**
**（c）加固**：第二道容差改为 `tol = 1e-6·max(1.0, max|coord|) + 3e-6`
（常数下界相对饱和值 `2.471e-6` 留约 1.2 倍余量）。

**（d）加固后回归（实测）**：

* `N=1024/2048/3072/4096` × 5 形状 = **20/20 全部构造成功**（含离朱记录的全部失败点：
  `cube@1750/2048/3072`、`sphere@3400/4096`、`cylinder λ=2@3072`、`cylinder λ=0.5@4096`）。
* **敏感性未损失**：真实偏移仍被抓住 ——
  单点平移 `1e-4`（`dev 7.07e-5`）/ `1e-5`（`7.07e-6`）由**两道**同时命中；
  单点平移 `1e-6`（`7.07e-7`）由**第一道**命中；晶格常数扰动 `1e-4`（`dev 2.0e-5`）两道同时命中。
  **第一道与 float32 距离计算无关（容差恒 `1e-9`），故任何 `>= 1e-9` 的真实偏移都无逃逸路径**；
  第二道单独可覆盖 `>= 1e-5` 的真实偏移。
* **拒绝证明复跑**：注入晶格常数 `×1.0001` 后 `verify_shape.py --quick` **退码 1**；
  从备份恢复后 `model.py` SHA256 **逐字节相同**（`4035dae6b1b24410…`，**当时基线**；
  该值随后续注释/文档修订而变，当前基线为 `3d72067b6b58ca4b…` —— 本节内 SHA 一律为**历史当时值**，仅用于证明「注入前后逐字节相同」，**不代表当前文件**），`--quick` 回到 78/78 退码 0。

## 17 N 阶梯 × 多 seed 同预算对照（仅提高 N 能否达到同预算 MLP 的性能）

### 17.0 目标与判定规则（**开工前固定，不得事后挑选或更改**）

**问题**：在同一训练预算下，三期（`n3d_shape`）**仅通过提高 `N`** 能否达到同预算 MLP 的性能。

**固定口径**（同时写进台账 `_meta.caliber` 与 `verify_ladder.py` 的**独立复述**；
两者不一致时 `verify_ladder.py` 退码 1、`run_ladder.py` 拒绝改口径并退码 2）：

| 维度 | 取值 |
| --- | --- |
| `preset` | `highacc`（`epochs=20` / `batch_size=128` / `lr=2e-3` / AdamW `weight_decay=1e-4` / `lr_schedule=cosine` / `grad_clip=1.0` / `readout_bias=True`） |
| dropout | **不引入** —— 三期 `Config` **无 dropout 字段**（预设也无该字段） |
| `shape` | `sphere`（**不传** `--cyl-aspect`） |
| `flow_axis` | `z` |
| `H` / `D` | `0.10` / `0.10`（`D = H`，硬约束 `D <= H` 的上界） |
| `space_radius` | **不传** `--space-radius` -> 取公式下界 `R_min`（逐档 `N` 由公式决定，见 §17.2） |
| `y_in` / `y_out` | `8` / `8` |
| `input_dim` / `output_dim` | `784` / `10` |
| `num_workers` | `0` |
| `input_scope` / `readout_scope` | `any_isolated` / `any_isolated` |
| `N` 阶梯 | `256, 512, 1024, 2048, 2976` |
| `seed` | `1, 2, 3, 7, 42, 43, 99, 123, 2024` |
| MLP 对照 | 每个 seed **各一次** `--arch mlp`（`784 -> 2048 -> 10`，`hidden_dim` 用默认 `2048`） |
| 达标判定（**事先固定**） | 某 `(N, seed)` 的 `test_acc >= 该 seed 的 MLP test_acc` 即视为**该点达标**；如实报告**全部**点，不因结果不利而改口径、**不事后择优** |
| 档 1 最优 `N` 判据（**事先固定**） | 档 1（`seed=42`）中 `test_acc` 最高者；**并列取较大 `N`** |

**档位**：

* **档 1**：`N` 阶梯 × `seed=42`（5 次 N3D + 1 次 MLP）；
* **档 2**：其余 8 个 seed × **档 1 选出的最优 `N`**（每个 seed 各 1 次 MLP）。

**本对照为同类比较**（同 preset、同 seed、同数据、同 `bs/lr/epochs`）；
**不得**把结果表述为对架构优劣的因果结论（两条局限声明见 §17.7）。

### 17.1 驱动方式与产物防撞名（硬要求）

运行器：`n3d_shape/run_ladder.py`（顺序驱动、可**断点续跑**）。
它只通过既有 CLI 参数驱动 `train.py`：

| 轮次 | 实际命令行（省略解释器与 `-X utf8`） |
| --- | --- |
| N3D | `train.py --preset highacc --arch neuron3d --seed S --shape sphere --n N --tag ladder_hacc` |
| MLP | `train.py --preset highacc --arch mlp --seed S --tag ladder_hacc_mlp` |

**为什么必须带 tag**：`train.full_checkpoint_name` **不含 preset / epochs / batch_size / lr**，
故不加 tag 时 `highacc + N=256 + seed=42` 会**覆盖**既有
`full_shapesphere_N256_y8x8_H0.1_D0.1_plfcc_axz_isany_rsany_s42.pt`
（历史纠正 #1 的同类缺陷）。

**为什么 MLP 还要再换一个 tag**：`full_checkpoint_name` 同样**不含 `arch`**。
若 N3D 与 MLP 共用同一 tag，同 `N`/`seed` 的两种架构会写**同一个文件名**而互相覆盖
（违反本计划"产物名必须两两唯一"的硬要求）。故 MLP 使用 `ladder_hacc_mlp`
（与 N3D 的 `ladder_hacc` 同前缀，防撞名意图一致，且两者都含 `ladder_hacc`）。

**MLP 不传 `--n`**：`N` 对 MLP 无意义（其参数只由 `input_dim/hidden_dim/output_dim` 决定），
故沿用预设 `N=256`，使 9 个 seed 的 MLP 产物名只差 `_s{seed}` 段，便于目视核对。

台账：`checkpoints/n3d_shape/_verify/ladder_runs.json`（**全部现场取数，禁止手填**）；
逐轮日志：`checkpoints/n3d_shape/_verify/log_ladder_{arch}_{N|Npreset}_s{seed}.txt`
（**显式 UTF-8** 写入，末尾写入**真实退出码**）。

### 17.7 必须写入的两条局限声明

**① `N` 不是唯一被改变的变量，且 `N` 与 MLP 的参数不对齐**
提高 `N` 会**同时**改变 `E`（736 -> 9,963）、`K`（9 -> 23）、`|S_in|`（193 -> 2,019）、
`|S_out|`（187 -> 2,057）与 `params`（154,874 -> 1,625,605）；因为**不传** `--space-radius`，
`R_min` 本身也随 `N` 增大（`0.701840 -> 1.589898`，`∝ N^(1/3)`）。
并且本对照的 `N` 与 MLP 的**参数并不对齐**：`N=2976` 为 **1,625,605**、MLP 为 **1,628,170**
（相差 `0.16%`），但两者**结构完全不同源**（稀疏分层 DAG vs dense `784->2048->10`）。
因此各点与 MLP 之间的差异**不可单独归因于 `N`**；本对照**不是**"只改 `N`"的干净对照。

**② 一期 98.64% 的参考线口径不同源，不得当作同预算达标线**
`checkpoints/_control/mlp_highacc_ep12_seed42.pt` 的实测 `test_acc = 98.64%`，
其产物内 `config` 与顶层字段实测为 `epochs=12`、`dropout=0.1`、`preset=highacc`；
而**本次全部 20 轮为 `epochs=20` 且无 dropout**（三期 `Config` **无 dropout 字段**，
`dropout` 不可引入）。两者**口径不同源**，故一期 `98.64%` 只能在讨论中作为**参考线**，
**不得**当作"同预算达标线"使用，也**不得**据此宣称本次结果"复现/反驳"了一期结论。

**③ 本对照为同类比较，不做因果结论**
结论只限"在同一 preset / 同 seed / 同数据 / 同 `bs/lr/epochs` 的口径内、仅提高 `N` 的实测表现"，
**不含**任何"A 架构优于/劣于 B"的因果主张；`Δ` 的量级（`-0.18 ~ 0.00 pp`）与 seed 噪声带
（MLP 极差 `0.19 pp`）同量级，任何超出"如实报告"的解读都不被本模块支持。

## 18 fc_dim：用两个全连接层包裹 N3D 核心，并与 MLP 做同参对照

### 18.0 目标与结构（`fc_dim` 单一配置开关）

**目标**：在主模型上新增**单一配置 `fc_dim`**，实现"**两端全连接包裹 N3D 核心**"的结构，
并以"**参数量最接近同预算 MLP 基线**"为口径做同参对照实测。

**启用（`fc_dim != 0`）时的精确结构与形状**：

```
x [B,784]
 ├─ (1) Linear(784 -> H) + bias(H) + ReLU                     [fc_in_weight (H,784) / fc_in_bias (H)]
 ├─ (2) 投影 P (|S_in|, H)  -> a_scope [B, |S_in|]            [proj_weight (|S_in|,H)]
 │       偏置复用 neuron_bias[in_scope_mask]；a_in[in_scope_mask] = a_scope.T
 ├─ (3) 核心：K 层稀疏递推（E 条边）+ 双副本，共享 edge_weight  ← **与关闭路径完全同一套核心**
 ├─ (4) h_sel = a_up[S_out] -> [B, |S_out|]                   ← **索引收集**（非掩码）
 ├─ (5) Linear(|S_out| -> H) + bias(H) + ReLU                 [fc_out_weight (H,|S_out|) / fc_out_bias (H)]
 └─ (6) Linear(H -> 10) + bias(10) -> logits（线性，无激活）    [head_weight (10,H) / head_bias (10)]
```

**三处关键设计（均已在代码与本节写明）**：

1. **关闭时"一个 FC 参数都不创建"**（仿 `readout_bias` 的既有先例），且 `W_in` / `edge_weight` /
   `neuron_bias` / `W_out` / `W_out_bias` 的**创建顺序与名称逐字保持改动前的样子** ——
   这是"关闭路径逐位不变"的结构前提（`verify_shape.py` 的 S12 按参数名与二期逐个
   `torch.equal` 比对，集合/顺序一变即失败）；
2. **启用时不再创建 `W_in` / `W_out` / `W_out_bias`** —— 它们分别被 (1)(2) 与 (5)(6) 取代
   （否则参数量会虚高，也不符合上面的结构公式）；
3. **(4) 用索引收集而非掩码**：非 `S_out` 神经元**根本不进入计算图**（即"输出侧死列归零"的
   结构化实现，而不是先算 `[B, N]` 再置零）。为不破坏既有契约，`readout_activations()` 的
   `[B, N]` 掩码语义**保持不变**（两条路径共用，供冒烟判据 [13] 与既有调用方使用），
   fc 路径的 (4)(5)(6) 由新增的 `fc_readout_logits()` 承担、由 `forward()` 分派。

### 18.2 六段形状契约与参数拆解

| 段 | 张量 / 参数 | 形状 | 类型 | 备注 |
| --- | --- | --- | --- | --- |
| (1) | `fc_in_weight` | `[H, input_dim]` | Parameter | LeCun 正态 `std = 1/sqrt(input_dim)` |
| (1) | `fc_in_bias` | `[H]` | Parameter | 零初始化 |
| (2) | `proj_weight` | `[|S_in|, H]` | Parameter | 均匀 `±1/sqrt(H)`；偏置复用 `neuron_bias[S_in]` |
| (3) | `edge_weight` / `neuron_bias` | `[E]` / `[N]` | Parameter | **与关闭路径同一套核心** |
| (4) | `out_scope_index` | `[|S_out|]` | buffer (int64) | **仅在启用时注册**（关闭路径 buffer 集不变） |
| (5) | `fc_out_weight` | `[H, |S_out|]` | Parameter | 均匀 `±1/sqrt(|S_out|)` |
| (5) | `fc_out_bias` | `[H]` | Parameter | 零初始化 |
| (6) | `head_weight` | `[output_dim, H]` | Parameter | Xavier 均匀 `±sqrt(6/(output_dim+H))` |
| (6) | `head_bias` | `[output_dim]` | Parameter | 零初始化 |

**参数量解析式**（`fc_dim != 0`）：
`params = H·input_dim + H + |S_in|·H + E + N + H·|S_out| + H + output_dim·H + output_dim`

实测核对（`fc_dim = -1`、`N = 825`、`seed = 42`）：解析式 == `count_parameters()`（见 §18.3），
且 `count_dense_weight_tensors() == 0` —— 新矩阵活在**特征空间**，因 `|S_in| <= N < N·y_out`，
不可能等于违规的 `[N·y_out, N·y_in]` 突触空间形状，故该判据无需豁免。

* 本表的 `params` / `E` / `|S_in|` / `|S_out|` 都是**构造期量**（只构造、不训练）；
  `test_acc` 与其它训练指标见 §18.5；

* 选中偏差**均为负或极小正**（最大 `+0.0209%`），即三期的参数量**略低于或基本等于** MLP 基线。

### 18.6 判定规则与两条限制声明（**事先固定，不得事后挑选**）

**判定规则**：**纯探索** —— 本对照只**如实报告** `params` / 偏差 / `E` / `K` /
`|S_in|` / `|S_out|` / `test_acc` 与配对差，**只陈述"在同参对齐口径下、9 个 seed 上三期的
`test_acc` 与同预算 MLP 的配对均值差为 `+0.0056 pp`（stdev 0.1374 pp）"这一实测事实**，
**不下**"某结构更优/更差"的结论。

**限制 ①：同参对齐只是"参数量接近"，不是"结构相同"，差异不可单独归因于包裹结构**
即使 `params` 已对齐到 ±0.5%（实测 -0.3166% ~ +0.0209%），`E`（2,566–2,611）、
`K`（恒 15）、`|S_in|`（576–600）、`|S_out|`（566–597）与**逐 seed 的 `N`（822–828）**仍各不相同；
MLP 是 `784 → 2048 → 10` 的**dense 全连接**，N3D+FC 是"全连接 + 稀疏 DAG 核心 + 全连接"的
**混合结构**，两者**完全不同源**。故任何差异**不可单独归因于**"两端全连接包裹"这一改动。

**限制 ②：search 解不唯一 + 单 seed 单点噪声**
`N` 的搜索解**不唯一**（`params(N)` 局部非单调，相邻 `N` 常给出接近的总参数），
本口径只声明**已实现的一种搜索方案**；且 `Δ` 的量级（`-0.21 ~ +0.21 pp`）与 seed 噪声带
（MLP 极差 0.19 pp）**同量级**，故**不足以支撑因果结论**。
另外：本轮**未**与一期 `98.64%`（`epochs=12` + `dropout=0.1` 口径，见 §17.7 限制 ②）
做同源比较；一期该值只能作**参考线**。
